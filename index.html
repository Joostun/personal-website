 Systems

PennOS: a UNIX-like operating system

PennOS is a UNIX-like operating system written in C that runs as a guest OS inside a single Linux process. Its processes are threads, and a timer interrupt drives a preemptive priority scheduler that puts processes to sleep, blocks parents while they wait on their children, and reaps zombies.

It has its own FAT-style file system, PennFAT, stored in a single host file that acts as a virtual disk. Each process gets its own file descriptor table pointing into a global one, the same way a real kernel does it.

On top sits a system call layer that keeps user code and kernel code apart, and a shell that talks to the OS only through those calls. The shell has job control with foreground and background jobs, Ctrl-C and Ctrl-Z, pipelines, redirection, and built-ins like ps and cat.

 Custom IC

Pipelined MAC with two 16×4 SRAMs

In Cadence Virtuoso, I started with a 6T SRAM bitcell, laid out DRC/LVS-clean and run through Quantus parasitic extraction. I expanded it into an SRAM module with precharge, a sense amplifier and a decoder.

Then I built a sequencer and a 4×4 array multiplier, and put it all together with custom flip-flops and a 12-bit accumulator into a pipelined multiply-accumulate unit fed by two 16×4 SRAMs, verified on end-to-end dot products. DONE rises 18 cycles after START.

I sized the critical path with logical effort and characterized setup and hold, clock-to-q, and energy per dot product. The finished MAC reached a minimum clock period of 1.1 ns, about 909 MHz, and I checked it for hold violations.

 FPGA

Speeding up code on an Ultra96

The Ultra96 pairs ARM cores with programmable logic on a Zynq UltraScale+ chip, and I worked through making real code faster on it, one layer at a time.

On the ARM side, I profiled a streaming pipeline (scale, filter, differentiate, compress) and read the compiler's assembly to see where the time went. I wrote content-defined chunking with a rolling hash, split the work across cores with coarse-grain parallelism and a two-core pipeline, and vectorized the hot loops with NEON SIMD.

On the FPGA side, I wrote matrix-multiply kernels in Vitis HLS, using pipelining and array partitioning to do more work every cycle, plus host code that keeps several buffers in flight so data transfers overlap with compute.
